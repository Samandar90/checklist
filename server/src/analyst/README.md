# Local analyst — «спросить у данных» без внешнего API

Самодостаточный движок аналитики: понимает вопросы по-русски, считает
показатели, объясняет причины, прогнозирует, находит аномалии и советует.
Ноль зависимостей, только TypeScript. Работает в Node и в браузере.

Папку `analyst/` можно скопировать в любой проект как есть.

## Как встроить (3 шага)

### 1. Опишите домен — что считаем и по чему режем

```ts
import { Analyst, AnalystConfig } from "./analyst";

const config: AnalystConfig = {
  name: "магазин",
  currency: "UZS",
  defaultMetric: "revenue",          // о чём речь, если метрика не названа
  primaryDimension: "category",      // "больше всего дал …" по умолчанию
  metrics: [
    { key: "revenue",  label: "Выручка", unit: "money", headline: true,
      synonyms: ["выручка", "продажи", "оборот", "доход"], drivers: ["orders", "avgCheck"] },
    { key: "orders",   label: "Число заказов", unit: "count", nounForms: ["заказ", "заказа", "заказов"],
      synonyms: ["заказы", "заказов", "чеки"] },
    { key: "avgCheck", label: "Средний чек", unit: "money", kind: "formula",
      deps: ["revenue", "orders"], compute: (s) => (s.orders ? s.revenue / s.orders : null),
      synonyms: ["средний чек", "чек"] },
    { key: "refunds",  label: "Возвраты", unit: "money", higherIsBetter: false,
      synonyms: ["возвраты", "возврат"] },
  ],
  dimensions: [
    { key: "category", label: "Категория", labelPlural: "категориям", synonyms: ["категория", "категории", "товары"] },
    { key: "store",    label: "Точка",     labelPlural: "точкам",     synonyms: ["точка", "магазин", "филиал"] },
  ],
};
```

Единицы: `money` / `percent` / `count` / `number`. Метрика — либо сумма
поля факта (`kind: "sum"`, по умолчанию), либо формула над суммами
(`kind: "formula"` + `deps` + `compute`). Измерения `weekday` и `month`
есть всегда — их не нужно объявлять.

### 2. Превратите данные в факты

Факт — строка `{ date, dims, measures }`. Одно событие может дать несколько
фактов (у отеля бронь даёт факт на дату заезда и по факту на каждую ночь).

```ts
const facts = orders.map((o) => ({
  date: o.createdAt.slice(0, 10),               // YYYY-MM-DD
  dims: { category: o.category, store: o.store },
  measures: { revenue: o.total, orders: 1, refunds: o.refunded ?? 0 },
}));
```

### 3. Спрашивайте

```ts
const analyst = new Analyst(config).load(facts);

analyst.ask("почему упала выручка за прошлый месяц?").text;
analyst.ask("какая категория растёт, а какая падает?").text;
analyst.ask("прогноз продаж на 2 недели").text;
analyst.ask("что сделать, чтобы поднять средний чек?").text;
analyst.narrative();                 // сводка абзацем
analyst.insights();                  // риски / возможности из config.rules
```

`ask()` возвращает `{ text, intent, confidence, followUps }`. `confidence < 0.5`
означает «вопрос не понят» — можно показать подсказки из `followUps` или
передать вопрос внешней модели.

## Что понимает

| Тип вопроса | Примеры |
|---|---|
| значение | «сколько было выручки в сентябре», «загрузка за 7 дней в выходные» |
| причина | «почему упала выручка», «из-за чего выросли отмены» |
| рейтинг | «какой канал приносит больше всего», «выручка по филиалам» |
| прогноз | «прогноз на 2 недели», «что будет с загрузкой завтра» |
| слабые/сильные дни | «какие дни впереди самые слабые», «пиковые даты в октябре» |
| динамика | «динамика ADR за 30 дней», «растёт ли средний чек» |
| аномалии | «были ли необычные дни», «всплески в августе» |
| советы | «что сделать, чтобы поднять загрузку», «как снизить отмены» |
| сводка | «как дела», «итоги за прошлый месяц» |
| несколько метрик | «где теряем деньги: долги, отмены или расходы» |

Периоды: сегодня, вчера, за неделю, за N дней/недель/месяцев, эта/прошлая
неделя, этот/прошлый месяц, в сентябре, 10.09, с 1 по 10 сентября, в выходные,
в будни, на N дней/недель вперёд. Значения измерений подхватываются из
данных: «выручка в Telegram» отфильтрует канал Telegram.

## Правила и советы (необязательно)

```ts
import { genericRules } from "./analyst";

config.rules = [...genericRules("revenue", "category"), (ctx) => {
  const r = ctx.value("refunds"), rev = ctx.value("revenue");
  if (!r || !rev || r / rev < 0.05) return null;
  return { id: "refunds", kind: "risk", severity: "warning", tags: ["refunds"],
    title: `Возвраты — ${Math.round((r / rev) * 100)}% выручки`,
    detail: `${ctx.fmt("refunds", r)} за период. Проверьте две самые возвращаемые позиции.` };
}];

config.advice = [{
  id: "bundle", tags: ["avgCheck", "revenue"], priority: 5,
  text: "Соберите комплект из двух самых ходовых товаров со скидкой 5% — средний чек растёт на 10–15%.",
  when: (ctx) => (ctx.value("avgCheck") ?? 0) > 0,
}];
```

Правило получает `RuleContext` (`value`, `series`, `groups`, `forecast`,
`anomalies`, `weekdayProfile`, `fmt`, `deltaPct`, `range`, `prevRange`,
`today`) и возвращает инсайт(ы) или `null`. Совет — текст с тегами метрик и
условием `when`; «что делать» и «почему» подбирают советы по метрике.

## Как это считает

- **Прогноз** — среднее по тому же дню недели за 12 недель × темп последнего
  месяца (ограничен 0,6–1,6), не ниже уже подтверждённого, коридор ±1σ.
- **Аномалии** — отклонение ≥ 2σ от среднего того же дня недели.
- **Причины** — объём × средняя цена, вклад каждого значения измерения в
  изменение, движение связанных метрик (`drivers`), самый необычный день.
- **Динамика** — линейная регрессия, наклон в % в неделю и r².

Все функции чистые и покрыты тестами (`analyst.test.ts`).

```
  core/types.ts     типы конфигурации и фактов

  core/dates.ts     календарь без библиотек

  nlu/stem.ts       токенизация и стемминг
  nlu/lexicon.ts    словарь намерений и периодов

  answer/compose.ts Query → текст ответа

```
